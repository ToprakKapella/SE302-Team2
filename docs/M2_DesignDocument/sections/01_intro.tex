\section{Introduction}
\draftnote{Toprak}
This document describes the design of the Exam Scheduler, a desktop application that reads classroom capacities and course registrations from CSV files and generates an exam schedule that satisfies the mandatory constraints of the requirements document (Milestone 1): no student has two exams in the same or in consecutive slots of a day, no student has more than two exams per day, one exam per classroom per slot, classroom capacity is at least the number of registered students, and every course is scheduled exactly once.

Section~2 gives the structural design (classes and packages), Section~3 the behavioral design (import, schedule generation, the no-solution case and the four views) and Section~4 the user interface. The application is written in Java with a JavaFX user interface; the installer bundles a Java runtime that includes JavaFX, so that the user does not have to install any software. The design in this document matches the implemented classes and packages.

\subsection{Changes since the requirements document}
The design follows the requirements document of Milestone~1 with the following changes:
\begin{itemize}
\item \textbf{Unknown students (Functional Requirement 24).} A registered student who is missing from the student list no longer causes the import to be rejected; the user is shown a warning instead. The student list is optional (Functional Requirement 3), so a missing entry may be an incomplete list rather than an error, and rejecting the file would block the user. All other invalid files (for example a missing capacity or a duplicated course) are still rejected with a clear message.
\item \textbf{Optional goals (Functional Requirement 23).} Two of the listed goals are offered: spreading the exams evenly over the exam period and finishing in the fewest days. The customer stated that optimization is not required, so the priority is a valid schedule; the other goals may be added later.
\item \textbf{Search time limit (Functional Requirement 14).} The search for a schedule stops after 20 seconds so that the user always gets an answer in reasonable time. Periods that are certainly impossible are detected before the search and the reason is shown; if the time limit is reached, the user is told that no schedule was found in time and is advised to add days or slots.
\item \textbf{Required software (Non-functional Requirement 2).} JavaFX is not part of a standard Java Runtime Environment, so the installer bundles a Java runtime with JavaFX. The user therefore does not need to install Java either, which exceeds the original requirement.
\end{itemize}
